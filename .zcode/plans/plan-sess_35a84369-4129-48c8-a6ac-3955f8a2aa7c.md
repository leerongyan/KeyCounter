## 目标

用 Rust 在 `native/` 子目录重写功能完全一致的 KeyCounter，实现轻量化（目标：exe ≤10MB，关面板后常驻内存 ~10-20MB，对齐 Clash Verge 水平）。**现有 Python 项目一行不动**，两者并存。

## 技术选型

| 模块 | 方案 | 说明 |
|---|---|---|
| 按键/鼠标采集 | windows-rs 低级钩子（WH_KEYBOARD_LL / WH_MOUSE_LL） | 回调只入内存 channel，无磁盘 I/O |
| 存储 | rusqlite (bundled SQLite) + WAL | 同一 schema；独立写线程 0.4s/500 条批量提交 |
| HTTP 服务 | tiny_http + serde_json | 127.0.0.1:8765；API 逐字段复刻 Python 契约 |
| 界面 | wry (WebView2) + tao 窗口 | **完全复用现有 web/ 文件夹**，界面零差异 |
| 托盘 | tray-icon | 菜单同 Python：打开面板/暂停/自启勾选/导出 CSV/导出 PNG/退出 |
| 热力图 PNG | tiny-skia + ab_glyph（微软雅黑） | 像素级复刻：1284×432、配色、圆角、图例 |
| 设置/自启 | data/settings.json 同格式；注册表 HKCU\...\Run 值名 KeyCounter | 与 Python 版互通 |

**关键行为 1:1 复刻**（已梳理完整契约）：按键归一化表（小键盘 vk 表、shift 归一、字母大写、alt_r→alt 等）、滚轮方向映射按 Python 现行为、侧键合并为 side、按住去重、暂停清空、鼠标距离采样规则（0.02~5s 且 ≥2px）、SQL 聚合与 substr 分组、top_keys LIMIT 15、日期范围语义、CSV utf-8-sig 带 BOM、Cache-Control/nosniff 响应头。

**核心卖点**：关面板时销毁窗口和 WebView（tao 事件循环存活，托盘重开时重建），Rust 常驻内核独立于界面——这就是 Clash Verge 关窗口后只剩 20MB 的模式，这次用 Rust 从一开始就做对。

## 已知差异（如实列出）

1. 托盘“导出完成”提示从气泡通知改为小对话框（Rust 托盘库无气泡 API）
2. 开机自启注册表值与 Python 版同名（KeyCounter），同时启用会互相覆盖——同一时间只对一个版本开自启
3. exe 名为 `KeyCounterNative.exe`，与 Python 版是两个程序；端口默认都是 8765，**不可同时运行**
4. 数据默认存 exe 旁 `data/`（可用 `--data-dir` 指向 Python 版的 data 目录以继承历史统计）

## 实施步骤

0. **环境检测**：cargo/rustc 是否可用；缺失则安装 rustup（MSVC 工具链）；确认 VS 链接器（你机器有 Visual Studio，大概率已具备）
1. **Cargo 骨架**：`native/` 项目，模块：hooks / keys / store / server / tray / ui / heatmap / settings / autostart
2. **采集+存储**：钩子回调入 channel → 批量写库；按键归一化单元测试
3. **HTTP 服务**：复用 web/，浏览器对比 Python 版；写 API 字段 diff 校验
4. **窗口+托盘**：三态关闭行为、托盘重开循环、暂停/自启/导出菜单
5. **导出**：热力图 PNG（像素级规格）+ CSV
6. **release 构建**：LTO + strip，实测体积与内存
7. **提交推送**（native/ 进同一仓库，Python 版不受影响）

## 验收标准

- 功能逐项对照 Python 版清单通过；网页界面渲染无差异（同一套前端）
- exe ≤ 10MB；关面板后常驻 ≤ 20MB
- Python 版可正常运行（互不干扰）
